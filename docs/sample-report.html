Executive summary

Example Co's server is reachable, backed up nightly, and its main file is well structured, but security has drifted since setup. The most serious issues are an out-of-date FileMaker Server version, one file without encryption at rest, and the Invoices file, where 9 of 14 accounts have Full Access and the Data API is enabled for everyday staff. The Contacts file also allows Guest access. None of these needs downtime to fix except the server update.

Scope and method

We reviewed the configuration of one FileMaker Server and the three files it hosts as of 30 October 2026, against RCC's best-practice rule set v1.0. Server settings were read through the FileMaker Admin API. Operating system settings were read by a read-only script run in a remote desktop session. File security was read from an accounts-only XML export of each file. Nothing was installed or changed on the server.

Not covered: account passwords and password policy, ongoing monitoring, log review, and any testing from outside Example Co's network. Items marked Not checked could not be read and should not be read as passing.

Remediation plan

Fails first, in the order we'd tackle them. Each is a change Example Co's administrator can make; RCC can help on request.

  1. Update FileMaker Server to 22.0.4 or later (SRV-01). Closes a critical published vulnerability. Needs a short maintenance window and a verified backup first.
  2. Turn off Guest in Contacts (FIL-03). Takes a minute and removes password-free access to customer data.
  3. Turn the Public firewall profile back on (OS-03), with inbound rules only for 443 and 5003, plus RDP if needed from known addresses.
  4. Move staff off Full Access in Invoices (FIL-01, FIL-04). Create or tighten a "Staff" set and keep Full Access to two named administrators.
  5. Rename or disable the Admin account in Invoices (FIL-02), and change the "Nightly import" schedule to run as a dedicated low-privilege account (SRV-07).
  6. Remove fmrest from "Staff" in Invoices (FIL-07) so only the web form account can use the Data API, and turn OData off on the server (SRV-05).
  7. Encrypt Contacts at rest (SRV-03) with the Developer Utility, then host the encrypted copy.
  8. Warnings: renew the certificate before 20 November, review port 8080 and AnyDesk, install pending Windows updates, replace the shared fmadmin account with named admins, add the database folder exclusion, and give each front-desk user their own login.
