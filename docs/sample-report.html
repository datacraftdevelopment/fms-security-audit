Executive summary

Example Co's server is backed up nightly and its Inventory file is close to how it was set up, but security has drifted since. The most serious issues are an out-of-date FileMaker Server version, a firewall profile turned off, one file without encryption at rest, and the Invoices file, where 9 of 14 accounts have Full Access and everyday staff can use the Data API. The Contacts file also allows Guest access. None of these needs downtime to fix except the server update.

Scope and method

We reviewed the configuration of one FileMaker Server and the 3 files it hosts as of 30 October 2026, against best-practice rule set v1.0. Server settings were read through the FileMaker Admin API. Operating system settings were read by a read-only script run in a remote desktop session. File security was read from an accounts-only XML export of each file. Nothing was installed or changed on the server.

Not covered: account passwords and password policy, ongoing monitoring, log review, and any testing from outside Example Co's network. Items marked Not checked could not be read and should not be read as passing.

Remediation plan

Fails first, then warnings. Each is a change Example Co's administrator can make; we can help on request.

  1. Full Access accounts (Invoices.fmp12). Move staff to privilege sets that match their work, and keep Full Access to two named administrators.
  2. Default account names (Invoices.fmp12). Rename or disable default accounts such as Admin and give administrators named accounts.
  3. Guest account (Contacts.fmp12). Disable the Guest account so every user must sign in.
  4. Everyone on one privilege set (Invoices.fmp12). Split users across privilege sets that match their roles.
  5. Extended privileges (Invoices.fmp12, Contacts.fmp12). Remove web and API extended privileges from privilege sets that don't need them.
  6. Firewall. Turn every firewall profile on, with inbound rules only for 443 and 5003 plus remote access from known addresses.
  7. FileMaker Server version. Update FileMaker Server to the minimum safe version or later, after a verified backup and in a maintenance window.
  8. Encryption at rest. Encrypt each unencrypted file with the FileMaker Developer Utility, then host the encrypted copy.
  9. Web technologies. Turn off every web technology (Data API, OData, WebDirect, XML, PHP) the client doesn't use.
  10. Wide privilege sets (Invoices.fmp12, Inventory.fmp12). Remove layout, script, value list and account management rights from sets used by non-developers.
  11. Shared logins (Invoices.fmp12). Give each person their own account.
  12. Listening ports. Identify each unexpected listening program and remove or firewall it if it isn't needed.
  13. Remote access services. Confirm each remote access service is needed and limited to known users and addresses; remove the rest.
  14. Patching. Install pending operating system updates and keep automatic updates on, with a maintenance window for restarts.
  15. Local administrators. Replace shared administrator accounts with named accounts, and keep the administrators group small.
  16. Antivirus exclusions. Exclude the live FileMaker database folder from real-time scanning, as Claris recommends, and scan backups instead.
  17. SSL certificate. Install a certificate from a trusted authority for the server's hostname and renew it before it expires.
  18. Script schedules. Run scheduled scripts under a dedicated account with only the privileges the script needs.
